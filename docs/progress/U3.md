# U3 — Account Vault, Secure Notes, Crypto Tools, Steganography

## Ringkasan

Rework antarmuka empat halaman (`/account-vault`, `/secure-notes`,
`/crypto-tools`, `/steganography`) mengikuti
`docs/desain/spesifikasi-ui.txt` §98–115 dan katalog U0 (`docs/progress/U0.md`):

- Markup baru memakai kelas `kx-*` + kelas halaman (`kx-av-*`, `kx-sn-*`,
  `kx-ct-*`, `kx-sg-*`); gaya khusus halaman di
  `static/css/halaman/<nama>.css` dimuat lewat blok `styles`.
  `style.css` dan `components.css` tidak diubah.
- Tanpa JavaScript inline, tanpa atribut `style=""` pada markup baru,
  ikon hanya lewat makro `ikon()`, teks tampil lewat `modules/strings.py`
  (pesan JS lewat atribut `data-msg-*` pada akar halaman).
- Route, API, kriptografi, dan format data tidak diubah; grant
  `account.reveal`, `note.open`, `note.edit`, `stego.extract`,
  `stego.download` tetap menjadi syarat aksi sensitif.
- Bug lama halaman Steganography diperbaiki: input `use_encryption` ganda
  (hidden `0` + checkbox bernama sama) membuat werkzeug membaca nilai
  pertama sehingga enkripsi muatan mati diam-diam di browser. Sekarang
  hanya ada satu input bernama `use_encryption` (hidden `#sg-use-enc`,
  default `"1"`), checkbox `#sg-enkripsi` tidak lagi membawa `name`.
- `modules/strings.py` ditambah konstanta pesan baru (tanpa mengubah nama
  field `passphrase` di form/JSON).

## Keputusan

1. **Branch**: prompt menyebut `u3-vault-notes-tools`, tetapi aturan keras
   sesi ini melarang membuat/mengganti branch; pekerjaan dikerjakan di
   branch aktif `ub-pratinjau`. Semua commit `[U3]` berada di branch itu.
2. **Lima kartu algoritma**: spesifikasi §108 menulis "empat kartu" tetapi
   mendaftar lima algoritma; yang aman adalah menampilkan semua yang benar-benar
   ada di kode (lima) tanpa menambah algoritma baru.
3. **Catatan — satu formulir dua mode**: editor memakai satu `#sn-form`
   untuk catatan baru (POST add) dan edit (POST edit + grant `note.edit`
   dipasang pada tombol simpan). Ini mengikuti struktur route yang ada
   tanpa menambah backend. Tidak ada pengatur waktu sembunyi otomatis
   (spesifikasi Notes tidak memintanya); tombol Tutup manual mengosongkan
   isi dari DOM.
4. **`konfirmasi-hapus.js` diperluas secara aditif** dengan opsi
   `pesan` (substitusi `{nama}`) sehingga modal hapus dapat menyebut nama
   item tanpa menyalin komponen.
5. **`kx-infobox-danger` page-scoped**: katalog U0 hanya punya varian
   info/warn; varian merah ditambahkan sebagai kelas halaman di
   `crypto_tools.css` dan `steganography.css` (halaman masing-masing),
   bukan mengubah `components.css`.
6. **Hasil ekstraksi stego inline**: hasil teks/berkas tampil di area
   `#stego-result` di dalam halaman (skeleton saat memuat, `kx-code` +
   Salin, infobox galat/berkas); `KX.toast` hanya untuk keberhasilan
   unduhan berkas agar tidak dobel notifikasi.
7. **Perbaikan `use_encryption`**: werkzeug `MultiDict.get` mengambil
   nilai pertama, jadi hidden `0` + checkbox `1` selalu mengirim `0`.
   Solusi: checkbox tanpa `name` + hidden tunggal yang dikelola JS
   (default `"1"` sehingga fallback tanpa JS tetap terenkripsi).
   Route tidak diubah (tetap membaca `use_encryption`).
8. **Istilah "Kunci rahasia"**: teks yang tampil ke pengguna memakai
   "Kunci rahasia"; nama field form/JSON `passphrase` dan nama fungsi
   tidak diubah (mis. `STEGO_PASSPHRASE_REQUIRED` kini berbunyi
   "Kunci rahasia wajib diisi bila dipilih sebagai kunci muatan.").
9. **mockup.pdf tidak dapat dibaca** (berkas korup/tidak terurai);
   `docs/desain/spesifikasi-ui.txt` dijadikan sumber kebenaran.

## Keterbatasan

- Form Crypto Tools tidak mengisi ulang nilai teks/kunci setelah POST
  (backend merender ulang halaman; paritas dengan perilaku halaman lama
  agar tidak mengubah route).
- Tanda kurung siku pada regex uji keseimbangan bracket membuat skrip
  bantu membaca `"`, sehingga regex pada `steganography.js` memakai
  `\x22` untuk tanda kutip ganda (perilaku sama).
- `mockup.pdf` tidak terbaca; verifikasi visual hanya lewat spesifikasi
  teks dan pemeriksaan render + tangkapan struktur halaman (Playwright
  tidak tersedia di lingkungan ini).

## Temuan di luar lingkup

- `_reauth_modal.html` masih memakai kelas lama (`form-control`) dan
  tiga atribut `style=""` — muncul di semua halaman, termasuk hasil render
  halaman U3; tidak diubah karena milik cakupan sesi lain.
- `werkzeug` `MultiDict.get` mengambil nilai pertama dari field bernama
  sama; halaman lain yang mengirim field ganda berisiko perilaku serupa
  (tidak ditemukan kasus lain di halaman U3).
- `static/css/style.css` masih berisi aturan lama (dihapus sesi
  pembersihan; tidak disentuh di sini).
